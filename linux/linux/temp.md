
## 1. Блок-схемы (Flowcharts)

Блок-схемы используются для визуализации алгоритмов, бизнес-процессов и логики работы программных модулей.

### 1.1 Линейная схема (Горизонтальная)

Схема с направлением слева направо (`LR`).

```mermaid
flowchart LR
    Init[Инициализация] --> Check{Проверка прав}
    Check -->|Успешно| Render["Отображение интерфейса <br/> (Dashboard)"]
    Check -->|Ошибка| Deny["Доступ запрещен <br/> (403 Error)"]
```

* `flowchart` — задает тип схемы;
* `LR` — порядок отрисовки (Left to Right);
* `<br/>` — единственный корректный способ переноса строки внутри узлов.

### 1.2 Ветвление и условия (Вертикальная)

Схема с ориентацией сверху вниз (`TD`).

```mermaid
flowchart TD
    NodeA([Старт процедуры]) --> NodeB[/Запрос параметров/]
    NodeB --> NodeC{Валидация}
    NodeC -- Не пройдена --> NodeD[Логирование ошибки]
    NodeD --> NodeB
    NodeC -- Пройдена --> NodeE[(Сохранение в БД)]
    NodeE --> NodeF([Завершение])
```

---

### 1.3 Справочник форм узлов

| Код | Внешний вид | Назначение |
| :--- | :--- | :--- |
| `id[Текст]` | Прямоугольник | Стандартный шаг процесса |
| `id(Текст)` | Скруглённые углы | Вспомогательное действие |
| `id([Текст])` | Овал / Стадион | Начальная или конечная точка |
| `id[[Текст]]` | Подпроцесс | Вызов внешнего скрипта / функции |
| `id[(Текст)]` | Цилиндр | База данных или реестр |
| `id((Текст))` | Круг | Точка соединения |
| `id{Текст}` | Ромб | Развилка / Логический оператор |
| `id[/Текст/]` | Параллелограмм | Входные или выходные данные |

### 1.4 Группировка блоков (Subgraphs)

Позволяет логически объединять связанные элементы.

```mermaid
flowchart TB
    subgraph Client ["Клиентский слой"]
        App[Мобильное приложение]
        Web[Веб-клиент]
    end

    subgraph Infrastructure ["Серверная инфраструктура"]
        Gateway[API Gateway]
        Auth[Служба аутентификации]
        Worker[Очередь задач]
    end

    App --> Gateway
    Web --> Gateway
    Gateway --> Auth
    Gateway --> Worker
```

## 2. Диаграмма последовательности (Sequence)

Служит для отображения хронологии сообщений и запросов между компонентами системы.

```mermaid
sequenceDiagram
    autonumber
    actor Client as Клиент
    participant Service as Сервис оплаты
    participant Gateway as Платёжный шлюз

    Client->>Service: Создать заказ
    activate Service
    Service->>Gateway: Инициализация транзакции
    activate Gateway
    Gateway-->>Service: Ссылка на оплату
    deactivate Gateway
    Service-->>Client: Перенаправление на форму

    Note over Client, Gateway: Пользователь вводит данные карты

    Client->>Gateway: Подтверждение платежа
    activate Gateway
    Gateway-->>Service: Webhook (Status: OK)
    deactivate Gateway
    Service-->>Client: Чек и подтверждение
    deactivate Service
```

## 3. Диаграмма классов (Class Diagram)

Отражает ООП-архитектуру: классы, методы, поля и связи между ними.

```mermaid
classDiagram
    class BaseEntity {
        +UUID id
        +DateTime createdAt
        +save() Void
    }

    class Account {
        +String username
        -String hashPassword
        +changePassword(String newPass) Bool
    }

    class Role {
        +String roleName
        +List permissions
    }

    BaseEntity <|-- Account : Наследование
    Account "1" o-- "*" Role : Агрегация
```

* Модификаторы доступа: `+` Public, `-` Private, `#` Protected.
* Обозначения связей: `<|--` (Inheritance), `o--` (Aggregation), `*--` (Composition).

## 4. Диаграмма Ганта (Gantt Chart)

Удобна для визуализации дорожных карт проектов и отслеживания дедлайнов.

```mermaid
gantt
    dateFormat  YYYY-MM-DD
    title План спринта разработки

    section Проектирование
    Анализ требований         :done, task1, 2024-03-01, 2024-03-04
    Архитектурный сессия      :done, task2, 2024-03-04, 3d

    section Имплементация
    Бэкенд API               :active, task3, after task2, 7d
    Фронтенд верстка         :active, task4, after task2, 5d

    section Релиз
    Нагрузочное тестирование :crit, task5, after task3, 3d
    Деплой на прод           :task6, after task5, 1d
```

## 5. Граф зависимостей компонентов

Выстраивается с помощью `flowchart` для наглядного отображения архитектуры модулей или библиотек.

```mermaid
flowchart BT
    React[React Core]
    Redux[Redux Toolkit]
    Router[React Router]
    AppUI[Пакет UI Components]

    AppUI --> React
    Redux --> React
    Router --> React
    MainApp[Основное приложение] --> AppUI
    MainApp --> Redux
    MainApp --> Router
```

## 6. Диаграмма состояний (State Diagram)

Используется для моделирования жизненного цикла объекта.

```mermaid
stateDiagram-v2
    [*] --> НоваяЗаявка

    НоваяЗаявка --> ВОбработке : Назначить оператора
    ВОбработке --> ОжидаетОплаты : Сформирован счет

    state ОжидаетОплаты {
        [*] --> Ожидание
        Ожидание --> Таймаут : Истекло время
    }

    ОжидаетОплаты --> Оплачено : Поступление средств
    ОжидаетОплаты --> Отменено : Отмена клиентом

    Оплачено --> Выполнено : Доставка
    Выполнено --> [*]
    Отменено --> [*]
```

## 7. Карта путешествия пользователя (User Journey)

Помогает оценить UX-проблемы и зафиксировать этапы работы пользователя с продуктом.

```mermaid
journey
    title Опыт регистрации в сервисе
    section Первое знакомство
      Переход по рекламе: 4: Гость
      Изучение лендинга: 3: Гость
    section Регистрация
      Ввод Email и пароля: 4: Гость
      Подтверждение почты: 2: Гость, Почтовый сервис
    section Онбординг
      Заполнение профиля: 5: Новый пользователь
      Прохождение тура по сервису: 4: Новый пользователь
```

## 8. Стилизация элементов

С помощью `classDef` можно гибко настраивать цветовую гамму узлов.

```mermaid
flowchart LR
    classDef primary fill:#2b580c,stroke:#639a67,color:#fff;
    classDef warning fill:#d9534f,stroke:#d43f3a,color:#fff;

    Node1[Нормальный режим]:::primary --> Node2[Критическая ошибка]:::warning
```

```mermaid
    "Redis" : 25
```
